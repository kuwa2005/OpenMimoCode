Open Mimo Code — CLI Reference

$ oimo

oimo は、AI コーディングエージェント Open Mimo Code のコマンドラインインターフェースです。 ターミナル内の対話 UI（TUI）、非対話のワンショット実行、リモートサーバー運用、モデル・セッション・ プロバイダの管理など、すべての操作をこの 1 つのコマンドで行えます。

$ oimo # 対話 UI を起動（既定コマンド） $ oimo run "テストを実行して" # 非対話で 1 回だけ実行 $ oimo --help # 全コマンド・オプションの一覧

概要

コマンドは基本 oimo <コマンド> [引数..] [オプション..] の形式です。 引数を省略して oimo だけを実行すると、カレントディレクトリをプロジェクトとして 対話 UI（TUI）が起動します。

コマンド一覧

コマンド説明

oimo runメッセージを渡して非対話で実行
oimo attach実行中の oimo サーバーに接続
oimo serveヘッドレスサーバーを起動
oimo acpACP（Agent Client Protocol）サーバーを起動
oimo sessionセッションの管理（一覧・削除・Claude 取り込み）
oimo models利用可能なモデルの一覧
oimo statsトークン使用量・コスト統計

oimo dbSQLite データベースの操作
oimo debugデバッグ・トラブルシューティング

引数を解析する .strict() モードが有効です。存在しないオプションを渡すとエラーになります。

クイックスタート

$ oimo # 対話 UI を起動（最も一般的な使い方） $ oimo run "このリポジトリの README を要約して" $ oimo -c # 直前のセッションを継続 $ oimo -m openai/gpt-5.6 # モデルを指定して起動（provider/model 形式） $ oimo --tor # Tor SOCKS5 経由で通信を匿名化

詳しいヘルプはいつでも oimo --help（コマンド全体）または oimo <コマンド> --help（個別コマンド）で表示できます。

グローバルオプション

oimo --help に表示される共通オプションです。既定コマンド（TUI）と serve / acp / attach は、このうちネットワーク関連の オプションを共有しています。

共通オプション

オプション説明
-h, --helpヘルプを表示
-v, --versionバージョンを表示
--print-logsログを stderr に出力
--log-levelログレベル DEBUG / INFO / WARN / ERROR
--pure外部プラグインなしで実行
--tor全通信を Tor SOCKS5 プロキシ経由にルーティング
--log <file>TUI セッションの質問と要約を Markdown ファイルに追記

ネットワークオプション（TUI / serve / acp 共通）

オプション説明既定値
--portリッスンポート0（自動）
--hostnameリッスンするホスト名127.0.0.1
--mdnsmDNS サービスディスカバリを有効化（hostname が 0.0.0.0 になる）false
--mdns-domainmDNS 用のカスタムドメインoimo.local
--corsCORS を許可する追加ドメイン（複数指定可）[]
--no-auth非ループバックアドレスで認証なし起動を許可（危険）false

TUI 起動オプション

オプション説明
-m, --model使用するモデル provider/model 形式
-c, --continue直前のセッションを継続
-s, --sessionセッション ID を指定して継続
--fork継続時にセッションをフォーク （--continue または --session と併用）
--prompt使用するプロンプト
--agent使用するエージェント
--never-asknever-ask モードで開始（権限系は対象外。実行中は /never-ask で切替）
--autonomy, --seSE 型自律実行モード（要件を聞いてロック → 証跡付きでノンストップ開発。compose エージェントを暗黙指定）
--trustワークスペース信頼確認をスキップしてそのディレクトリを信頼
--dangerously-skip-permissions明示的に拒否されていない権限を自動承認（危険）
--auto上記と同じ自動承認に加え、ワークスペース信頼確認もスキップ（危険）

oimo [project]

既定コマンド

対話 UI（TUI）を起動します。

$ oimo [project] [options]
引数説明
project作業を開始するディレクトリのパス（省略時はカレントディレクトリ）

例

# カレントディレクトリで対話 UI を起動
oimo

# 指定ディレクトリをプロジェクトとして起動
oimo ~/my-project

# モデルを指定して起動
oimo -m openai/gpt-5.6

# 直前のセッションを続行
oimo -c

# 特定セッションをフォークして続行
oimo -s ses_abc123 --fork

# SE 型自律実行モード（要件ロック → 証跡付き自動実装）
oimo --se

# Tor 経由で匿名化（--auto と併用で信頼確認もスキップ）
oimo --tor --auto
起動時にワークスペースの信頼確認が行われます。--trust / --auto / --dangerously-skip-permissions でスキップできます。

oimo run [message..]

メッセージを渡して非対話で 1 回だけ実行します。パイプ入力された標準入力もメッセージとして扱われます。また -- 以降のトークンはメッセージに追加されます。

$ oimo run [message..] [options]
引数説明
message..送信するメッセージ（複数指定すると連結）
オプション説明
--command実行するコマンド（引数は message で渡す）
-c, --continue直前のセッションを継続
-s, --sessionセッション ID を指定して継続
--fork継続前にセッションをフォーク （--continue / --session 必須）
--shareセッションを共有（共有 URL を生成）
-m, --model使用するモデル provider/model 形式
--agent使用するエージェント
--format出力形式 default（整形済み）/ json（生の JSON イベント）
-f, --fileメッセージに添付するファイル（複数指定可）
--titleセッションのタイトル（省略時はプロンプト先頭から自動生成）
--attach <url>実行中の oimo サーバーに接続して実行 例: http://localhost:4096
-p, --passwordBasic 認証パスワード （既定: MIMOCODE_SERVER_PASSWORD）
--dir <path>実行ディレクトリ（アタッチ時はリモート上のパス）
--portローカルサーバーのポート（省略時はランダム）
--variantモデルバリアント（プロバイダ固有の reasoning effort 等）
--thinkingthinking ブロックを表示
--role注入メッセージのロール user / assistant（assistant はテキストをモデル出力として注入して継続）
--auto明示的に拒否されていない権限を自動承認（危険）

例

# ワンショット実行
oimo run "このリポジトリのテストを実行して結果を教えて"

# --command でコマンドを指定
oimo run --command "bun test" --dir packages/opencode

# 標準入力からメッセージを渡す
cat spec.txt | oimo run "この仕様を実装して"

# ファイルを添付してレビューを依頼
oimo run -f src/main.ts -f src/util.ts "これら 2 ファイルのレビューをして"

# 直前のセッションをフォークして続行
oimo run -c --fork "ここまでの続きをやって"

# プロセスイベントを JSON で受信
oimo run --format json "3 ファイルに分割して"

# 実行中のサーバーへ接続して実行
oimo run --attach http://127.0.0.1:4096 "リモートで実行して"

oimo attach <url>

実行中の oimo サーバーに接続し、そのサーバーに対して対話 UI（TUI）を起動します。

$ oimo attach <url> [options]
引数説明
url接続先サーバーの URL 例: http://localhost:4096
オプション説明
--dir作業ディレクトリ（ローカルに無ければリモート上のパスとして送信）
-c, --continue直前のセッションを継続
-s, --sessionセッション ID を指定して継続
--fork継続時にセッションをフォーク （--continue / --session と併用）
-p, --passwordBasic 認証パスワード （既定: MIMOCODE_SERVER_PASSWORD）

例

# ローカルで起動したサーバーに接続
oimo serve --port 4096 &
oimo attach http://127.0.0.1:4096

# SSH ポートフォワードでリモートのサーバーに接続
ssh -N -L 4096:127.0.0.1:4096 user@remote-host
oimo attach http://127.0.0.1:4096

oimo serve

ヘッドレス（UI なし）の oimo サーバーを起動します。リモートホストや CI 環境でサーバーだけを立ち上げ、別のマシンから oimo attach / oimo run --attach で接続する用途に使います。

$ oimo serve [options]

例

# ポート 4096 でサーバーを起動
oimo serve --port 4096

# パスワード付きで起動（非ループバックへ公開する場合）
MIMOCODE_SERVER_PASSWORD=secret oimo serve --hostname 0.0.0.0 --port 4096

# mDNS でネットワーク内から発見可能にする
oimo serve --mdns --port 4096
非ループバックアドレス（0.0.0.0 等）にバインドするには MIMOCODE_SERVER_PASSWORD の設定（または危険な --no-auth）が必要です。 認証ユーザー名は MIMOCODE_SERVER_USERNAME（既定 oimo）。

oimo acp

ACP（Agent Client Protocol）サーバーを起動します。ヘッドレスサーバーを起動し、標準入出力を NDJSON ストリームで ACP エージェントとして橋渡しします。

$ oimo acp [network-options] [--cwd <dir>]
オプション説明
--cwd作業ディレクトリ （既定: カレントディレクトリ）
--port / --hostname / --mdns / --mdns-domain / --cors / --no-authネットワークオプション（前掲の共通オプション参照）

例

# ACP サーバーをポート 4096 で起動
oimo acp --port 4096

oimo session <list|delete|import-claude>

セッションの管理を行います。

$ oimo session list [options]
$ oimo session delete <sessionID>
$ oimo session import-claude [--force]

サブコマンド

サブコマンド説明
listセッションの一覧を表示。--format json で JSON 出力、TTY では対話ピッカー（矢印キー + Enter でそのセッションを TUI で再開）
delete <sessionID>セッションを削除
import-claudeClaude Code のセッション（~/.claude/projects）を oimo に取り込み
オプション説明
-n, --max-count直近 N 件に制限 （list）
--format出力形式 table / json（既定: table）
--forcemtime キャッシュを無視して全セッションを再同期 （import-claude）

例

# 直近 20 件を一覧
oimo session list -n 20

# JSON で取得（スクリプト処理用）
oimo session list --format json

# セッションを削除
oimo session delete ses_abc123

# Claude Code のセッションを取り込む
oimo session import-claude
oimo session import-claude --force

oimo models [provider]

利用可能なモデルの一覧を表示します。各モデルの解決済みウィンドウと、どのトークン数で圧縮されるかも表示されます。

$ oimo models [provider] [options]
オプション説明
providerモデルを絞り込むプロバイダ ID （位置引数）
--verboseコスト等のメタデータを含む詳細出力
--refreshmodels.dev のキャッシュを再取得して表示

例

# 全モデルを一覧
oimo models

# openai プロバイダのみ
oimo models openai

# キャッシュを更新して詳細表示
oimo models --refresh --verbose
設定の検証にも使えます。プロバイダが未設定で不正な設定をしていると、ここでモデルが解決できずに分かります。

oimo stats

トークン使用量とコストの統計を表示します（OVERVIEW / COST & TOKENS / MODEL USAGE / TOOL USAGE のセクションで構成）。

$ oimo stats [options]
オプション説明
--days <N>直近 N 日分を表示 （0 は今日。既定: 全期間）
--tools <N>ツール使用量の上位 N 件を表示 （既定: 全部）
--models [N]モデル統計を表示（既定は非表示。数値を渡すと上位 N 件）
--project <name>プロジェクトで絞り込み （既定: 全プロジェクト。空文字で現在のプロジェクトのみ）

例

# 全期間の統計
oimo stats

# 直近 7 日、モデル上位 10・ツール上位 5
oimo stats --days 7 --models 10 --tools 5

# 現在のプロジェクトのみ
oimo stats --project ""

oimo providers <list|login|logout|whoami>

エイリアス: oimo auth

AI プロバイダと資格情報（API キー・OAuth）を管理します。

$ oimo providers <list|login|logout|whoami> [options]

サブコマンド

サブコマンド説明
list (ls)プロバイダと資格情報の一覧（auth.json の内容と、環境に見つかったプロバイダ向け環境変数）
login [url]プロバイダにログイン。URL を渡すとその OAuth サーバー（.well-known/opencode）から認証フローを取得
logout設定済みプロバイダからログアウト（対話で選択）
whoami現在のログインユーザー情報を表示
オプション説明
-p, --providerログインするプロバイダ ID （選択をスキップ）
-m, --methodログインメソッドのラベル （選択をスキップ）

例

# 対話でプロバイダにログイン
oimo auth login

# プロバイダを直接指定（例: xiaomi MiMo）
oimo auth login -p xiaomi

# 独自 OAuth サーバーから認証フローを取得してログイン
oimo auth login https://opencode.example.com

# 一覧と確認
oimo auth list
oimo auth whoami
oimo auth logout

oimo agent <create|list>

エージェントの作成・一覧表示を行います。エージェントは役割（build / plan / compose 等）と権限（ツールセット）を持ちます。

$ oimo agent create [options]
$ oimo agent list
オプション説明
--path <dir>エージェントファイルを生成するディレクトリ
--descriptionエージェントが何をするか
--modeエージェントモード all / primary / subagent
--tools有効化するツールのカンマ区切り （既定: all。bash, read, write, edit, glob, grep, webfetch, actor, task）
-m, --model使用するモデル provider/model 形式

例

# エージェント一覧
oimo agent list

# 全引数を渡して非対話で作成
oimo agent create \
  --path ./agent \
  --description "README とドキュメントを整えるレビューワ" \
  --mode subagent \
  --tools "read,write,edit,glob,grep"

# 対話で作成（引数を省略するとプロンプトで聞かれる）
oimo agent create

oimo mcp <list|auth|logout|add|debug>

MCP（Model Context Protocol）サーバーの管理を行います。

$ oimo mcp <list|auth|logout|add|debug> [options]

サブコマンド

サブコマンド説明
list (ls)MCP サーバーとその状態を一覧表示
addMCP サーバーを追加（対話形式。スコープ・名前・種別 local/remote・コマンド・URL・OAuth 設定を入力）
auth [name]OAuth 対応 MCP サーバーで認証。auth list で認証状態を確認
logout [name]MCP サーバーの OAuth 資格情報を削除
debug <name>OAuth 接続をデバッグ（initialize ハンドシェイク、HTTP ステータス、OAuth ディスカバリ等）

例

# 対話で MCP サーバーを追加（--type 等のフラグは無し）
oimo mcp add

# 一覧と認証状態
oimo mcp list
oimo mcp auth list

# サーバー名を指定して OAuth 認証
oimo mcp auth github-mcp

# 接続をデバッグ / 資格情報を削除
oimo mcp debug github-mcp
oimo mcp logout github-mcp
oimo mcp add は完全に対話式です。--type / --command 等の フラグは存在しないため、プロンプトに従って入力してください。

oimo plugin <module>

エイリアス: oimo plug

npm のプラグインモジュールをインストールし、設定（oimo.json）を自動で更新します。

$ oimo plugin <module> [options]
オプション説明
-g, --globalグローバル設定にインストール （既定: プロジェクト）
-f, --force既存のプラグインバージョンを置き換え

例

# プロジェクトにインストール
oimo plugin @some/plugin

# グローバルにインストール / 強制アップデート
oimo plugin @some/plugin -g
oimo plugin @some/plugin -f

oimo export [sessionID]

セッションデータを JSON（{info, messages}）として標準出力に書き出します。sessionID を省略すると対話で選択します（パイプ時は最新）。

$ oimo export [sessionID] [--sanitize]
オプション説明
--sanitize会話本文・ファイルパス・ツール入出力等の機微情報を [redacted:...] に置き換えてマスク

例

# セッションをファイルに書き出し
oimo export ses_abc123 > session.json

# 機微情報をマスクして書き出し
oimo export --sanitize > session-sanitized.json

# 対話で選択して書き出し
oimo export

oimo import <file>

エクスポートされたセッション JSON、または共有 URL からセッションを取り込みます。

$ oimo import <file|share-url>
引数説明
fileJSON ファイルのパス、または https://…/share/<slug> 形式の共有 URL

例

# ローカルファイルから取り込み
oimo import session.json

# 共有 URL から取り込み
oimo import https://opncd.ai/share/abc123

oimo github <install|run>

GitHub Agent を管理・実行します。

$ oimo github install
$ oimo github run [--event <type>] [--token <pat>]

サブコマンド

サブコマンド説明
installGitHub Agent をインストール。GitHub の origin リモートを持つリポジトリ内で実行し、opencode-agent App を導入して .github/workflows/opencode.yml を生成
runGitHub Agent を実行（ワークフロー内で使用）
オプション説明
--event実行する GitHub モックイベント（issue_comment / pull_request 等）
--tokenGitHub の personal access token

例

# GitHub リポジトリ内で Agent をセットアップ
oimo github install

# 特定イベントで Agent を実行（テスト用途）
MODEL=openai/gpt-5.6 GITHUB_RUN_ID=1 oimo github run --event pull_request
oimo github run は主に GitHub Actions のワークフローから使うため、 環境変数 MODEL / GITHUB_RUN_ID / PROMPT 等が必須です。

oimo pr <number>

指定した GitHub PR のブランチをチェックアウトして oimo（TUI）を起動します。PR 本文に共有 URL が含まれる場合は、そのセッションを取り込んで続行します。

$ oimo pr <number>
gh CLI と git リポジトリが必要です。フォークからの PR は自動でリモートを追加します。

例

# PR #42 のブランチで作業を開始
oimo pr 42

oimo db <[query]|path|migrate>

SQLite データベースの操作ツールです。

$ oimo db [query] [--format <json|tsv>]
$ oimo db path
$ oimo db migrate

サブコマンド

サブコマンド説明
[query]SQL クエリを実行して結果を出力（既定: tsv）。クエリなしで実行すると対話式 sqlite3 シェルを起動
pathデータベースファイルのパスを表示
migrate旧 JSON データを SQLite に移行（既存データとマージ）

例

# DB の場所を確認
oimo db path

# セッション数を数える
oimo db "select count(*) from session"

# 結果を JSON で取得
oimo db "select id, title from session limit 5" --format json

# 対話シェルを起動
oimo db

oimo debug <subcommand>

デバッグ・トラブルシューティング用の各種ユーティリティです。

$ oimo debug <subcommand> [options]
サブコマンド説明
config解決済み設定（JSON）を表示
lspLSP デバッグ: diagnostics <file> / symbols <query> / document-symbols <uri>
rgripgrep デバッグ: tree / files [--query --glob --limit] / search <pattern> [--glob --limit]
fileファイルシステムデバッグ: read <path> / status / list <path> / search <query> / tree [dir]
scrap既知の全プロジェクトを表示
skill利用可能な全スキルを表示
snapshotスナップショットデバッグ: track / patch <hash> / diff <hash>
agent <name>エージェント設定の詳細を表示。--tool / --params でツールを直接実行
pathsグローバルパス（data / config / cache / state）を表示
wait無期限に待機（デバッグ用）

例

# 設定の確認
oimo debug config

# パスの確認
oimo debug paths

oimo upgrade [target]

oimo を最新版、または指定バージョンへアップグレードします。インストール方法（curl / npm / brew 等）を自動検出します。

$ oimo upgrade [target] [options]
引数 / オプション説明
targetアップグレード先のバージョン 例: 0.1.48 または v0.1.48（省略時は最新）
-m, --methodインストール方法を明示 curl / npm / pnpm / bun / brew / choco / scoop

例

# 最新版へアップグレード
oimo upgrade

# 特定バージョンを指定
oimo upgrade 0.1.48

# インストール方法を指定
oimo upgrade -m brew

oimo uninstall

oimo をアンインストールし、関連ファイルを削除します。何が削除されるか事前に確認できます。

$ oimo uninstall [options]
オプション説明
-c, --keep-config設定ファイルを残す
-d, --keep-dataセッションデータとスナップショットを残す
--dry-run削除せずに削除対象だけを表示
-f, --force確認プロンプトをスキップ

例

# 削除対象を確認
oimo uninstall --dry-run

# 設定とデータを残してアンインストール
oimo uninstall -c -d

# 確認なしで完全削除
oimo uninstall -f

oimo completion [shell]

シェル補完スクリプトを生成します。

$ oimo completion [bash|zsh|fish]

例

# bash: 出力を設定ファイルに追記
oimo completion bash > ~/.oimo/completion.bash
echo "source ~/.oimo/completion.bash" >> ~/.bashrc

# zsh / fish
oimo completion zsh > ~/.zfunc/_oimo
oimo completion fish > ~/.config/fish/completions/oimo.fish
シェルの補完設定への反映方法は、お使いのシェルによって異なります。上記は一般的な例です。

環境変数

よく使われる環境変数の一覧です。フラグで指定できるものは、環境変数でも同じ挙動にできます。

環境変数説明
MIMOCODE_SERVER_PASSWORDサーバーの Basic 認証パスワード（serve / attach / run --attach で使用）
MIMOCODE_SERVER_USERNAME認証ユーザー名 （既定: oimo）
MIMOCODE_TOR1 で全通信を Tor SOCKS5 経由に （--tor と同じ）
MIMOCODE_TOR_PROXYTor プロキシの指定 （既定: socks5h://127.0.0.1:9050）
MIMOCODE_PURE1 で外部プラグインなし （--pure と同じ）
MIMOCODE_LOGセッションログ（Markdown）の出力パス （--log と同じ）
MIMOCODE_AUTONOMY1 で SE 型自律実行モード （--se と同じ）
MIMOCODE_DANGEROUSLY_SKIP_PERMISSIONS1 で権限の自動承認 （--auto と同じ）
MIMOCODE_ENABLE_ANALYSIStrue でメトリクス送信を明示的に有効化 （既定: 無効）
MIMOCODE_ENABLE_MIMO_FREEtrue で xiaomimimo 無料チャネルを明示的に有効化 （既定: 無効。中国サーバーへの送信を遮断）
MIMOCODE_AUTO_SHAREoimo run でセッションを自動共有
MIMOCODE_DISABLE_CLAUDE_IMPORT初回起動時の Claude Code セッション取り込みを無効化
GH_REPOアップグレード取得元リポジトリ （既定: kuwa2005/OpenMimoCode）
MIMOCODE_INSTALL_SCRIPT_URLインストーラースクリプトの URL を上書き
MIMOCODE_UNINSTALL_DIRアンインストール対象ディレクトリ （既定: ~/.oimo/bin）
oimo github run はワークフロー実行用のため、MODEL / GITHUB_RUN_ID / PROMPT / MENTIONS / GITHUB_TOKEN などの環境変数を読みます。詳細は oimo github run --help を確認してください。

ワークフロー例

1. リモートホストでサーバー運用し、ローカルから接続

TUI が遅くなる環境（SSH 直打ちなど）では、表示をローカルに、実行をリモートに分離できます。

# リモートホスト
oimo serve --port 4096

# ローカルホスト: SSH ポートフォワードを作成
ssh -N -L 4096:127.0.0.1:4096 user@remote-host

# ローカルホスト: 別のターミナルから接続
oimo attach http://127.0.0.1:4096

# 非対話で実行する場合
oimo run --attach http://127.0.0.1:4096 "ビルドを直して"

2. Tor による匿名利用

# ローカル Tor デーモン（ポート 9050）を起動してから
oimo --tor
oimo run --tor "リポジトリを調査して"

3. SE 型自律実行（要件ロック → 証跡付き自動開発）

oimo --se ~/my-project

4. セッションの共有と引き継ぎ

# 実行結果を共有 URL にする
oimo run --share "調査結果をまとめて"

# 共有 URL を取り込んで継続
oimo import https://opncd.ai/share/abc123
oimo -s <取り込まれたセッションID>

5. MCP サーバーの追加とツール利用

# 対話で追加（名前・種別・コマンド/URL を入力）
oimo mcp add
oimo mcp list
oimo mcp auth github-mcp   # OAuth 対応サーバーなら認証

6. データベースの確認と移行

oimo db path
oimo db "select count(*) from session" --format json
oimo db migrate   # 旧 JSON データを SQLite へ移行

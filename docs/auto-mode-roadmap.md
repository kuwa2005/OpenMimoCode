# Auto モード ロードマップ

現状は **Auto(無料)**（公開 ID: `auto/free`）のみ実装する。有料・併用は後続。

## 公開 ID（予約）

| 公開 ID | UI 名（案） | 状態 | 候補列 |
|---------|-------------|------|--------|
| `auto/free` | Auto (無料) | **現行** | 無料枠のみ。FCC カタログ＋認証済み候補を first-frame フォールバック |
| `auto/paid` | Auto (有料) | 将来 | 有料モデルのみの順序付き候補 |
| `auto/hybrid` | Auto (無料＋有料) | 将来 | **無料を先に試し、能力不足と判断したら有料へ** |

名前空間 `auto/*` を空けておく。有料込みの「全部入り」を単に `auto` にしない（無料専用と混同しやすい）。

## Auto (無料＋有料) の意図

```text
優秀な無料枠 → … → 弱い無料枠 まで試す
        │
        └─「お馬鹿な無料枠では対応しきれない」と判断
              → 有料枠へエスカレーション
```

- 目的: 普段は無料枠を使い切り、難しい依頼だけ有料に落とす
- 「対応しきれない」は **レート制限だけでは足りない**。品質・能力不足（ツール失敗の反復、計画不能、ユーザー意図の取り違え等）を検知して有料へ上げる
- first-frame 障害フォールバック（429/5xx）とは **別レイヤ**: 障害切替はリクエスト前半、能力エスカレーションはターン／タスク単位で後から設計する

## 能力エスカレーション（将来設計メモ）

障害フォールバック（現行 `auto/free`）と混ぜない。

| 層 | トリガ | 挙動 |
|----|--------|------|
| L1 障害 failover | 429 / 5xx、first-frame 前 | 次の **同ティア** 候補（無料→無料） |
| L2 能力 escalate | 無料候補を使い尽くした／品質シグナル | **有料候補列**へ。同一ターン再試行 or 次ターンから有料固定 |

品質シグナル案（未実装・要検証）:

- 同一ツール失敗・同一編集の反復（既存 try-best / repeated-step と整合）
- モデル自身の「できない」表明＋検証失敗
- ユーザー明示の「もっと賢いモデルで」
- コンパクション／コンテキスト破綻が無料枠の窓制限に起因する場合

**やらないこと（現行方針の延長）:**

- 部分出力後に別モデルでサイレントやり直し（first-frame 規則）
- 有料を黙って先頭に差し込む（コスト不意打ち）
- 無料カタログに有料 ref を混ぜる

## 実装順序（将来）

1. `auto/free` 安定化＋FCC カタログ同期運用（現行）
2. `auto/paid` — 同じ Failover エンジンに有料候補カタログを載せるだけ
3. `auto/hybrid` — L1 は無料列、L2 で有料列へ。UI でコスト注意を明示
